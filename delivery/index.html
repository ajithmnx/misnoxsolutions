How We Deliver

How We Work

Four phases. For each one: what we do, what you get, and what has to be true before we move on.

01

Discover

Understand the environment before proposing anything.

What Happens

  • Current systems inventory and integration touchpoints
  • Data flow mapping — what moves, when, and who owns it
  • Control objectives: approval thresholds, SoD requirements, audit needs
  • Constraints: licensing, upgrade cycles, internal capacity

You Receive

Integration Assessment document
Systems and data flow map
Prioritised gap list with indicative effort

Exit Criteria

You confirm the findings are accurate and agree the priorities.
02

Design

Document the solution before writing code.

What Happens

  • Integration architecture and pattern selection
  • Field-level data mappings and transformation rules
  • Error handling, retry, and exception routing design
  • Security model: accounts, permissions, credential storage
  • Test scenarios including negative and edge cases

You Receive

Integration Design Document
Field mapping specification
Test plan with acceptance criteria

Exit Criteria

You sign off the design document.
03

Build & go live

Build, test, and deploy against the agreed design.

What Happens

  • Development in a non-production environment
  • Unit and integration testing against the test plan
  • User acceptance testing with your team
  • Cutover rehearsal and rollback plan
  • Production deployment in a controlled window

You Receive

Working integration in production
UAT sign-off record
Cutover runbook and rollback procedure
Technical documentation and handover pack

Exit Criteria

You have signed off testing, the integration is live, and your team can run it.
04

Support

Keep it running and improve it over time.

What Happens

  • Monitoring and alerting configured to your channels
  • Exception review and resolution
  • Platform upgrade impact assessment
  • Periodic optimisation review

You Receive

Support handbook
Monitoring and alert configuration
Regular exception and performance reporting

Exit Criteria

Reviewed with you at agreed intervals.

Governance

During the Project

Regular Updates

A short written update at an agreed rhythm: what moved, what is blocked, what changed.

Proper Handover

Documentation and a walkthrough, so your team can run the integration without us.

One Person Accountable

The person who designs your integration stays with it through build and go-live.
